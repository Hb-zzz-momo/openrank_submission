# OpenRank 课设汇报：整体工作流与核心代码

## 一句话主张

本项目是一个面向 LLM 开源项目的生态健康度可视化平台：系统从 OpenDigger 获取 GitHub 开源项目指标，通过 Flask 后端完成缓存、清洗、统计和 AI 报告生成，再由 Vue3 前端展示项目树、雷达图、指标表格、收藏和智能分析结果。

## 汇报故事线

1. 背景：单纯看 star、fork 难以判断开源项目是否健康。
2. 目标：构建一个能从活跃度、治理质量、多样性、LLM 适配度、可持续性五个维度分析项目的平台。
3. 方案：前后端分离，后端负责数据接口和计算，前端负责交互可视化。
4. 核心实现：OpenDigger 数据抓取与缓存、健康度计算、雷达图归一化、AI 分析报告。
5. 效果展示：首页大屏、项目选择、雷达对比、指标排序、智能分析、登录收藏。
6. 总结：项目完成了从数据获取、指标建模、可视化分析到部署上线的完整闭环。

## 整体工作流

### 1. 数据配置层

项目仓库列表和指标列表放在 `backend/config.json` 中。后端根据配置知道要分析哪些项目、抓取哪些 OpenDigger 指标。

工作流：

`config.json` → 读取项目列表 → 生成 OpenDigger API 地址 → 请求远程 JSON 指标。

### 2. 数据同步层

`backend/data_fetcher.py` 定期从 OpenDigger 拉取数据，将月度指标转成统一格式：

```json
{"month": "2025-01", "count": 123.45}
```

然后写入 SQLite 数据库 `backend/openrank.db`。

### 3. 后端服务层

`backend/main.py` 创建 Flask 应用，注册三个蓝图：

- `api_bp`：OpenDigger 指标、LLM 汇总、AI 报告
- `auth_bp`：登录注册、JWT 鉴权
- `favorites_bp`：用户收藏

后端通过 `/api/*` 暴露给前端。

### 4. 数据处理层

后端从数据库中读取 `openrank` 和 `activity` 等指标，计算最近 12 个月均值、波动标准差、归一化分数和综合健康度。

核心思想：

`原始月度指标` → `最近 12 个月` → `均值/波动` → `归一化` → `health_score`

### 5. 前端交互层

`frontend/src/views/HomeView.vue` 是主页面。用户从左侧项目树选择最多 3 个项目，前端请求后端 API 获取指标，并生成雷达图和表格。

工作流：

`选择项目` → `fetchAvgMetric 请求指标` → `loadRadarData 归一化` → `ECharts 展示雷达图` → `表格排序和结论生成`

### 6. AI 分析层

用户点击“生成智能分析”后，前端把雷达图中的项目和五维指标传给 `/api/llm/report`。后端先生成结构化数字摘要，再调用 OpenAI；如果调用失败，则可以走规则兜底逻辑。

### 7. 部署层

前端执行 `npm run build` 生成静态文件，部署到 `/var/www/openrank`；nginx 监听 80 端口，静态页面直接返回，`/api/` 代理到 Flask 后端 `127.0.0.1:8000`。

部署访问链路：

`浏览器` → `nginx:80` → `Vue 静态页面`

`浏览器 /api 请求` → `nginx /api/ 反向代理` → `Flask:8000` → `SQLite/OpenDigger/OpenAI`

### 代码块 2：OpenDigger 数据抓取与缓存

位置：`backend/api/opendigger.py`

```python
def fetch_and_cache_data_db(api_url: str, platform: str, entity: str, repo: str | None, metric: str):
    repo_key = repo or ""

    row = MetricSeries.query.filter_by(
        platform=platform, entity=entity, repo=repo_key, metric=metric
    ).first()

    if row and row.updated_at:
        if datetime.utcnow() - row.updated_at < timedelta(hours=CACHE_TTL_HOURS):
            return {"data": row.to_records(), "cached": True}

    resp = requests.get(api_url, timeout=30)
    resp.raise_for_status()
    data = resp.json()

    formatted_data = [
        {"month": k, "count": v}
        for k, v in data.items()
        if isinstance(k, str) and len(k) == 7 and k.count("-") == 1
    ]

    payload = json.dumps(formatted_data, ensure_ascii=False)

    if row:
        row.data_json = payload
    else:
        row = MetricSeries(
            platform=platform, entity=entity, repo=repo_key, metric=metric,
            data_json=payload
        )
        db.session.add(row)

    db.session.commit()
    return {"data": formatted_data, "cached": False}
```

讲解重点：

- 先查本地数据库，24 小时内有缓存就不请求远程，减少接口压力。
- OpenDigger 原始 JSON 被统一转换成 `{month, count}`。
- 使用 upsert 思路：有记录就更新，没有记录就新增。
- 这是项目“数据从哪里来”的核心代码。

### 代码块 4：健康度得分公式

位置：`backend/metric_utils.py`

```python
def calculate_health_score(
    openrank_norm: float,
    activity_norm: float,
    stability_norm: float,
    weights: Optional[Dict[str, float]] = None
) -> float:
    if weights is None:
        weights = {"openrank": 0.5, "activity": 0.3, "stability": 0.2}

    score = (
        weights["openrank"] * openrank_norm +
        weights["activity"] * activity_norm +
        weights["stability"] * stability_norm
    )
    return round(score, 4)
```

讲解重点：

- 健康度不是单一指标，而是多指标加权。
- OpenRank 权重最高，代表项目影响力和治理质量。
- Activity 代表社区活跃度。
- Stability 由波动程度反推，波动越小越稳定。

### 代码块 6：雷达图五维指标映射与归一化

位置：`frontend/src/views/HomeView.vue`

```javascript
const radarMetricMap = {
  activity: 'activity',
  governance: 'openrank',
  diversity: 'new_contributors',
  llm_fit: 'stars',
  sustainability: 'bus_factor'
}

const loadRadarData = async () => {
  const repoMetrics = await Promise.all(
    selectedIds.value.map(async id => {
      const [org, repo] = id.split('/')
      const raw = {}

      for (const key of radarKeys) {
        const odMetric = radarMetricMap[key]
        raw[key] = await fetchAvgMetric(org, repo, odMetric)
      }

      return { id, raw }
    })
  )

  radarData.value = repoMetrics.map(r => ({
    repo: r.id,
    metrics: radarKeys.reduce((acc, key) => {
      const raw = r.raw[key] || 0
      const max = maxByKey[key]
      const min = minByKey[key]
      acc[key] = max === min ? (raw === 0 ? 0 : 0.5) : (raw - min) / (max - min)
      return acc
    }, {})
  }))
}
```

讲解重点：

- 页面展示的是五个业务维度，但底层用 OpenDigger 的真实指标支撑。
- 不同指标量纲不同，例如 stars 和 bus_factor 数值范围完全不同，所以需要归一化到 0 到 1。
- `Promise.all` 并发获取多个项目的指标，提升前端响应速度。

### 代码块 7：AI 报告生成接口

位置：`backend/api/opendigger.py`

```python
@api_bp.route("/llm/report", methods=["POST"])
@rate_limit(max_requests=5, window_seconds=60)
def generate_llm_report():
    payload = request.get_json(silent=True) or {}
    projects = payload.get("projects", [])

    if not projects:
        raise ApiException(400, "至少需要一个项目")

    enriched = []
    for p in projects:
        repo = p.get("repo", "unknown")
        metrics = p.get("metrics") or {}
        vals = list(metrics.values())
        score = sum(vals) / len(vals) if vals else 0.0
        enriched.append({"repo": repo, "metrics": metrics, "score": score})

    enriched.sort(key=lambda x: x["score"], reverse=True)

    summary_lines = []
    for idx, p in enumerate(enriched, start=1):
        m = p["metrics"]
        summary_lines.append(
            f"{idx}. {p['repo']} —— 总体得分约 {p['score']:.2f}，"
            f"活跃度 {m.get('activity', 0):.2f}，"
            f"治理质量 {m.get('governance', 0):.2f}，"
            f"多样性 {m.get('diversity', 0):.2f}。"
        )
```

讲解重点：

- 后端先把前端传来的雷达图指标转成结构化数字摘要。
- 排序后把最强项目放在前面，方便大模型生成更清晰的对比报告。
- 接口加了限流，避免频繁调用 AI 接口造成资源浪费。

## 可能被老师问到的问题

### 为什么要缓存 OpenDigger 数据？

因为 OpenDigger 数据是远程 JSON，请求次数多会慢，也可能失败。缓存到 SQLite 后，页面刷新可以优先读本地数据，系统更稳定。

### 为什么要做归一化？

不同指标量纲不一致，例如 stars 可能是几十万，bus_factor 可能只有个位数。直接比较没有意义，所以统一缩放到 0 到 1。

### 为什么选雷达图？

雷达图适合展示多个项目在多个维度上的相对强弱，能直观看出项目的优势和短板。

### AI 报告是否完全依赖大模型？

不是。后端先计算结构化分数和摘要，再把明确的数据传给大模型。大模型主要负责把数据转成可读的分析文本。

### 项目还可以怎么改进？

可以增加更多指标权重配置、支持用户自定义项目、加入历史趋势预测、优化大包体积、把 Flask 开发服务替换成 gunicorn 等生产服务。
